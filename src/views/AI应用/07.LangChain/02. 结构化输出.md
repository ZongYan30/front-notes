# 结构化输出

## 含义

让某个`Agent`始终遵循某种`JSON`输出格式，比如：

```json
{
  "name": "张三",
  "phone": "13300001111",
  "address": "四川省成都市xxxx"
}
```

## 场景

- **信息抽取**

  ```json
  {
    "name": "张三",
    "phone": "13300001111",
    "address": "四川省成都市xxxx"
  }
  ```

- **分类或打标签**

  ```json
  {
    "category": "退款",
    "urgency": "高"
  }
  ```

- **情感分析**

  ```json
  {
    "sentiment": "负面",
    "score": 0.92,
    "reason": "用户对等待时间不满"
  }
  ```

- **生成数据库记录**

  ```json
  {
    "customer_name": "李明",
    "phone": "138...",
    "appointment_time": "2026-08-21 14:00"
  }
  ```

- ...

## 实现

- 工具调用：强制让模型调用工具实现结构化输出
- 模型服务商：让模型服务商提供实现
- 自动抉择：langchain 自动决策使用

### 法一:工具调用方式

- 创建一个agent，使用`ToolStrategy`实现结构化输出

:::code-group

```python [agents/address_parser.py]
from langchain_python.core.config import openai_settings, anthropic_settings
from langchain.agents import create_agent
from langchain.agents.structured_output import ProviderStrategy, ToolStrategy
from pydantic import BaseModel, Field
from langchain_python.tools import tools, ask_user_question
from langchain.chat_models import init_chat_model

# 测试文本
# 你把货发到我公司就行，地址是哈尔滨南岗区大街金爵万象三期三号楼，让快递联系主管田佳玉，电话就打13312345678

# 可以使用三种方式定义: pydantic/dataclass/TypedDict
class AddressInfo(BaseModel):
    """用户收货地址信息"""

    name: str = Field(description="姓名")
    phone: str = Field(description="电话")
    address: str = Field(description="地址")


# 方法1：创建model
model = init_chat_model(
    model=anthropic_settings.default_model,
    model_provider="anthropic",
    thinking={"type": "disabled"},#结构化输出必须禁用思考链
)

# 方法2：创建agent
agent = create_agent(
    model=model,
    system_prompt="请根据提供的信息提取出收货地址的结构化信息，如果提供的信息不全，必须使用 ask_user_question 工具让用户补充信息",
    tools=[ask_user_question],
    response_format=ToolStrategy(AddressInfo),
)
```

```json [langgraph.json]
  "graphs": {
    "agent": "langchain_python.agents.main_agent:agent",
    "address_agent": "langchain_python.agents.address_parser:agent"
  }
```

:::

ToolStrategy工作原理

```text
model节点内部
1. 生成工具：AddressInfo(name, phone, address)
2. 绑定工具： tools + AddressInfo
3. 请求模型: 要求模型强制调用工具 Any
4. 模型返回工具调用

if 调用AddressInfo:
  model节点内部调用
else if tools调用:
  ToolNode节点调用

5. 最终执行end节点
```

### 法二：交给模型服务商处理

有的阿模型服务商支持json_schema，比如anthropic，kimi等。

```text
Provider --> 百炼聚合商 --> 模型服务商(重点也要看这个是否支持)
```

```python
# 切换为ProviderStrategy即可，把schema传递给模型，由模型自己实现
agent = create_agent(
    model=model,
    system_prompt="请根据提供的信息提取出收货地址的结构化信息，如果提供的信息不全，必须使用 ask_user_question 工具让用户补充信息",
    tools=[ask_user_question],
    response_format=ProviderStrategy(AddressInfo),
)
```

**注意: ProviderStrategy一旦使用，那么不会调用我们提供的Tools。**

这个时候如果信息不完整，也不会再调用`ask_user_question`工具了。

```text
你把货发到我公司就行
```

### 法三：自动抉择

```python
agent = create_agent(
    model=model,
    system_prompt="请根据提供的信息提取出收货地址的结构化信息，如果提供的信息不全，必须使用 ask_user_question 工具让用户补充信息",
    tools=[ask_user_question],
    response_format=AddressInfo,# 自动抉择
)
```

langchain内部有一个对照表(只有国外的)，像国内的不认识的模型，自动退回到工具调用。

## 最佳实现

1. Agent 带工具吗？

**不需要**

- 使用`ProviderStrategy`

- 仔细选择模型服务商

  必须支持`json_schema`

**需要**

- 使用`ToolStragegy`

2. 需要结构化返回的场景，一般都会新建agent，一个结构对应一个agent

```
地址结构化返回：地址agent
情感结构化返回：情感agent
```
