# 网关访问链路

![客户端携带 Virtual Key 和模型分组名，AI 网关路由到模型部署并使用对应上游凭证请求供应商](https://zongyan30.github.io/front-assets/agent/ai-gateway-access-chain.png)

## Provider

上游供应商，比如 Deepseek、百炼、月之暗面、智谱、OpenAI、...

## Credential
进入Lite LLM --> Models+Endpoints --> Credentials --> 创建凭证
凭证，一个凭证包含：

- Provider: Qwen
- Base Url: 服务商请求地址
- API Key: 模型Api Key

最佳实践：
- 至少包含三个账号独立的凭证，以便实现熔断+降级
- 证书名称建议设置为：`<Provider>-<账号>-<Key编号>`，全英文

## Deployement

一个 Deployeement （模型部署）包含：

- 上游供应商的一个模型
- 模型分组名（public model name）
- 使用的证书

分组名的最佳实践

`类型-能力`

类型：chat、vision、embedding、...

能力：basic、standard

| 类型/能力 | basic                                            | standard                                         |
| --------- | ------------------------------------------------ | ------------------------------------------------ |
| chat      | 处理简单问答、摘要和文本改写。                   | 处理多轮对话、较复杂的指令和日常内容生成。       |
| vision    | 识别图片中的主要内容，<br />回答简单的看图问题。 | 理解图片中的细节、图表和文档页面。               |
| embedding | 为短文本生成向量，支持基础语义检索。             | 为一般文档生成向量，支持知识库检索和相似度匹配。 |

操作: 
Add Model --> 上游Provider(Qwen) --> LLM Names(3.7-max) --> Mode健康测试(/chat/completions) --> 选择已有的凭证 --> 测试连通 --> 确定保存

然后点击 All Models 看对应的deployement

## Virtual Key

创建一个 Virtual Key，用于你的客户端和 LiteLLM 交互。

操作：
Create Virtual Key，配置如下：
```js
Organization:忽略
Team:忽略
Name:项目名 (Deal Pilot)
Model: All
```

保存Virtual Key

## agent替换环境变量
现在已经搭建好网关了，agent连接的模型应该是走我们网关的模型
1. agent从直连变为通过网关连接：
```yaml
- Old:
模型地址: 百炼地址
模型: 3.7-max

- Current:
模型地址: 网关地址 (http://localhost:4000/v1)
模型: 网关指定模型 (chat_standard)
```

所以将env替换为
```yaml
OPENAI_API_KEY=sk-your-VirtualKey
OPENAI_BASE_URL=http://localhost:4000/v1
```

2. 将langfuse提示词的config中的模型替换为网关指定模型
```json
{
  "description": "",
  "model_config": {
    "model": "chat-standard",
    "thinking": "false"
  }
}
```

3. `make dev`启动agent，发送`你好`，测试连通。

## 解决连通失败
上面连通失败，报错：
```sh
OpenAIInvalidRequestError(
  'Error code: 400 - {\'error\': {\'message\': "litellm.UnsupportedParamsError: qwen_ai_platform does not support parameters: [\'thinking\'], for model=qwen3.7-max. To drop these, set `litellm.drop_params=True` or for proxy:

`litellm_settings:
 drop_params: true`
. 
 If you want to use these params dynamically send allowed_openai_params=[\'thinking\'] in your request.. Received Model Group=chat-standard
Available Model Group Fallbacks=None", \'type\': \'invalid_request_error\', \'param\': None, \'code\': \'400\'}}'
)
```

报错原因：
LiteLLM不知道当前的千问已经支持了thinking参数，所以直接打回这个请求给了客户端。

解决方法：
查看千问文档，发现还有一个参数可以传递
```js
extra_body={"enable_thinking": true}
```

回到agentServer的`create_model`中，更改参数传递即可。
```python
from langchain.chat_models import init_chat_model
from deal_pilot.config.openai_settings import openai_settings

def create_model(**kwargs):
    # 不允许用户自定义 model_provider
    kwargs.pop("model_provider", None)  # 删除 model_provider 字段
    thinking = kwargs.get("thinking", True)
    kwargs.pop("thinking", None)
    kwargs.pop("extra_body", None) # 不允许配置extra_body参数

    config = {
        "model": openai_settings.default_model,
        "model_provider": "openai_reasoning",
        "extra_body": {"enable_thinking": thinking},# 更改此处
    }
    config.update(kwargs)

    model = init_chat_model(**config)
    return model
```

再次测试，连通成功。


## 完成剩余工作

现在已经创建一个账号了，接下来创建另外两个即可。
```

    key2 - credential2

    key3
```
