# Logging Callback
我们的观测平台是在lagfuse上，目前存在网关LiteLLM之后，观测平台分散了。

需要把观测平台集中到langfuse上，LiteLLM提供了Logging Callbacks功能。

## 配置Logging Callbacks
Settings --> Logging Callbacks --> Add
```sh
Callback: Langfuse OTEL
Public Key: langfuse_public_key
Secret Key: langfuse_secret_key
Host URL: http://langfuse-web:3000
Tracing Environment:-
```
Host: 连接到Langfuse web的主机地址。 因为当前服务都是在docker中的，docker容器之间想要通信，需要通过服务名来访问。
(http://localhost:3000)会在LiteLLM所处容器中去找3000端口，那么肯定找不到。

Tracing Environment: 追踪的环境，目前langfuse的环境有`default`和`sk-experiment`，此处配置无效(属于liteLLM的bug)，需要到`docker-compose.yml`中配置。

`docker-compose.yml`新增:
```yaml
litellm:
    environment:
        LANGFUSE_TRACING_ENVIRONMENT: gateway
        OTEL_ENVIRONMENT_NAME: gateway
```

## 验证
配置好，重启服务
```sh
docker compose up -d --force-recreate litellm
```

回到langsmith，发送一条消息，去langfuse的Tracing查看是否出现了一个环境为`gateway`的observation。
