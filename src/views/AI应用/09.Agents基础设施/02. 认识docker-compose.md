# 认识 Docker Compose

## 动机

在真实的企业开发中，无论是传统的后端应用，还是 Agent 应用，都需要一系列基础设施作为支持。

比如，一个 Agent 应用需要：

- `langfuse`：实现 Agent 的观察与评估
- `PostgreSQL`：存储业务数据，比如：用户会话、检查点、DataSet 等等
- `Redis`：存储临时数据，比如缓存、消息队列等
- `minio`：对象存储，保存静态数据
- `clickhouse`：存储日志、指标等分析型数据，可进行高速统计查询
- `pgadmin`：数据管理控制面
- ...

这些基础设施在开发阶段，往往都是以 Docker容器 的形态启动。

如果分开管理，就涉及到一系列的问题：

1. 容器之间如何通信

   只能手动的把它们加到一个docker网络。

2. 每个容器需要的环境变量不一致

   只能在每次启动容器时，手动给它设置环境变量。

3. 容器间存在依赖怎么处理？

   只能在脑海中记住它们的依赖关系：先启动被依赖的容器，再启动依赖它的容器。

我们希望以上问题能以更加简洁、优雅、自动化的方式处理。

这就要依靠`Docker Compose`。

`Docker Compose`称之为容器编排，它允许通过一个配置文件（`docker-compose.yml`），集中性的管理一个企业级工程所需要的所有容器。

简单来说：`Docker Compose`提供一个入口，通过该入口，统一管理多个容器。

## 认识 docker-compose.yml

```yaml
name: deal-pilot  # 提供一个分组名称，所有的容器都收归进该分组，通常为项目名称

services: # 核心配置，描述当前分组下，有哪些服务，每个服务对应一个容器
	pgadmin: 
	langfuse-worker:
	langfuse-web:
	clickhouse:
	minio:
	redis:
	postgres:
	
volumes:	# 卷柜声明，每个卷柜就是一个磁盘存储空间
	postgres_data:
	clickhouse_data:
	clickhouse:logs:
```

## 常用命令

```shell
# 创建并在后台启动所有容器
docker compose up -d

# 查看容器状态
docker compose ps

# 持续查看所有容器的日志，按 Ctrl+C 退出
docker compose logs -f

# 停止容器，但保留容器
docker compose stop

# 启动已经停止的容器
docker compose start

# 重启所有容器
docker compose restart

# 停止并删除容器和网络，不会删除数据卷
docker compose down

# 重新创建并在后台启动所有容器
docker compose up -d --force-recreate
```

## 核心改动
1. env文件新增docker-compose.yml所需要的变量

```sh
# 以下配置仅用于基础设施启动的环境变量
# ------langfuse-----
LANGFUSE_WEBHOOK_WHITELISTED_HOST=host.docker.internal

# [可选]Langfuse 事务邮件（不要在示例文件中填写真实邮箱或 SMTP 安全密码）
LANGFUSE_SMTP_CONNECTION_URL=
LANGFUSE_EMAIL_FROM_ADDRESS=

# [可选]Langfuse Ask AI（复用文件上方的 OpenAI 兼容模型配置）

LANGFUSE_OPENAI_BASE_URL=${OPENAI_BASE_URL}
LANGFUSE_OPENAI_DEFAULT_MODEL=${OPENAI_DEFAULT_MODEL}
```

      timeout: 5s
      retries: 10

  langfuse-minio:
    image: cgr.dev/chainguard/minio
    restart: always
    entrypoint: sh # 容器启动时通过 sh(shell) 执行 command 中配置的命令
    # 容器启动时执行的命令
    # mkdir -p /data/langfuse: 为 langfuse 创建存储桶
    # minio server --address ":9000" --console-address ":9001" /data
    # 启动 minio 服务，所有的存储桶位置：/data
    command: -c 'mkdir -p /data/langfuse && minio server --address ":9000" --console-address ":9001" /data'
    environment:
      MINIO_ROOT_USER: root
      MINIO_ROOT_PASSWORD: 12345678
    ports: # 宿主端口映射
      - 9000:9000
      - 9001:9001
    volumes:
      - langfuse_minio_data:/data
    healthcheck:
      test: ["CMD", "mc", "ready", "local"]
      interval: 1s
      timeout: 5s
      retries: 5
      start_period: 1s

  langfuse-redis:
    image: docker.io/redis:7
    restart: always
    volumes:
      - langfuse_redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 3s
      timeout: 10s
      retries: 10

  # 专为 langfuse 使用的 postgres 数据库
  langfuse-postgres:
    image: docker.io/postgres:17
    # 重启策略
    # no: 不自动重启，默认值
    # on-failure: 只有容器以非 0 状态码异常退出时才重启
    # always: 不管正常退出还是异常退出，都会自动重启
    # unless-stopped: 手动停止容器后，Docker服务重启仍然保持停止
    restart: always
    healthcheck: # 健康检查
      # 运行命令，命令运行成功会将该容器标记为健康
      test: ["CMD-SHELL", "pg_isready -U root -d postgres"]
      interval: 3s # 每隔三秒钟运行一次
      timeout: 3s # 最多等待命令执行3秒
      retries: 10 # 超时或失败后重试的次数
    environment: # 启动容器时向它注入环境变量
      POSTGRES_USER: root # 账号
      POSTGRES_PASSWORD: 123456 # 密码
      POSTGRES_DB: postgres # 默认数据库
      TZ: Asia/Shanghai # 容器操作系统时区
      PGTZ: Asia/Shanghai # 客户端会话的时区
    volumes:
      # 数据保存到卷柜 langfuse_postgres_data（必须在volumes中有声明）
      - langfuse_postgres_data:/var/lib/postgresql/data

volumes:
  langfuse_clickhouse_data:
  langfuse_clickhouse_logs:
  langfuse_minio_data:
  langfuse_redis_data:
  langfuse_postgres_data:
