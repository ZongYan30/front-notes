# 系统流程梳理

梳理下当前的系统流程

```text
运行 1ifespan，直到yield，准备好接收请求

请求到来一>
- 找到第一个中间件，将其执行放入到一个try当中
- 移交、移交、移交、路由（路由表）
- 注入参数（某些参数DI）
- 运行依赖函数，得到生成器，迭代第一个yield session(事务）
- 路由函数执行（处于同一个事务环境)
- 继续迭代生成器，直到全部迭代完成（自动提交、自动回滚、关闭事务）

- 当中间件正常执行完，把它返回的信息进行响应
- 当第一个中间件执行期间报错，就进入异常处理
    根据注册的异常类型和对应的函数，找到函数执行
    响应函数的返回结果
    将异常信息打印到控制台
```

## 事务

事务 ACID：原子、一致、隔离、持久。
标准流程：
`begin → DML(增删改) → commit` 正常提交
`begin → DML → rollback` 异常回滚

**事务生命周期 = 从 begin 到 commit/rollback 的整个时间段**
根据这个时长，分为**短事务**、**长事务**。

## 长事务

`begin` 之后，中间夹杂大量**非数据库阻塞逻辑**，很久才 commit，事务持续几百毫秒～数秒甚至分钟。

```python
async with db.begin():
    # 1. 查库（持有锁）
    user = await get_user()
    # 2. 发起外部HTTP请求，等待第三方接口 2s（阻塞！锁一直不释放）
    resp = await httpx.get("https://xxx-third-api.com")
    # 3. 复杂文件解析、大循环计算 3s
    data = parse_big_excel("xxx.xlsx")
    # 4. 最后才更新、提交
    user.balance = resp.amount
```

优点： 数据强一致性
缺点： 事务生命周期长，锁持有时间长，影响并发性能

## 短事务

事务开启后，**只做少量数据库操作，立刻提交，毫秒级结束**，中间不夹杂网络 IO、用户等待、复杂业务计算。

**典型特征**

1. 生命周期极短：几毫秒～几十毫秒；
2. 事务内只有纯 DB 操作：select /insert/update /delete；
3. 无外部阻塞：不调用 HTTP、文件读写、等待用户输入、大循环计算；
4. 锁持有时间极短，释放迅速。

优点： 性能高，锁释放快，并发性能好
缺点： 数据一致性弱

## 优化代码

当前的session代码是这样的，这样会导致一个路由中执行多个service时，会变成长事务

```python
async def get_db() -> AsyncGenerator[AsyncSession]:
    async with get_session_factory().begin() as session:
        yield session
```

改造代码为短事务，将session的提交关闭权交给service层。

当一个路由中,出现多个service时，其中一个service关闭了事务，那么接下来当其他service使用session时，会自动创建新的事务。

```text
一次路由:
    - service1: 开启事务
    - service2: 提交+关闭事务
    - service3: 自动创建新的事务
```

```python
async def get_db() -> AsyncGenerator[AsyncSession]:
    session = get_session_factory()()
    session.begin()
    try:
        yield session
    except:
        await session.rollback()
        raise
    else:
        await session.commit()
    finally:
        await session.close()
```
