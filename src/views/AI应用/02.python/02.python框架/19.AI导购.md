# AI导购

实现一个 AI 导购的小功能，初步结合学习的相关知识。

## 解决方案

在 AI 时代下，解决方案才是上游。当解决方案确定之后，就可以指挥 AI 或自己逐步推进开发。

先明确业务范围和流程：

```text
用户进入商品详情页
  ↓
初始化 AI 导购
  ↓
AI 自动介绍商品
  ↓
用户继续提问
  ↓
AI 根据商品资料和历史对话回答
  ↓
用户可以查看或清空会话
```

第一期只实现“基于商品资料的多轮对话”，暂不涉及商品搜索、购物车、下单、实时库存查询和工具调用。

### 1. 设计 model

AI 导购需要依赖用户和商品，因此先确认已有的 `User`、`Product`、`Category`、`Sku` 模型。AI 自己需要保存的是“某个用户针对某个商品的对话”。

一个用户可以和多个商品对话，一个商品也可以被多个用户对话，所以使用独立的 `AiConversation` 表，并用 `user_id + product_id` 标识一条会话：

```text
一个用户 + 一个商品 = 一条会话
```

第一版使用 JSONB 保存有序消息列表，结构简单，方便整体读取并直接传给 AI：

```json
[
  {"role": "system", "content": "商品信息和导购规则"},
  {"role": "assistant", "content": "商品介绍"},
  {"role": "user", "content": "这个产品适合什么人？"},
  {"role": "assistant", "content": "适合人群说明"}
]
```

`ai_conversation.py`

```python [model/ai_conversation.py]
from sqlalchemy import ForeignKey
from sqlalchemy.dialects.postgresql import JSONB
from sqlalchemy.orm import Mapped, mapped_column

from zy_python_project.model.base import Base, TimestampMixin


class AiConversation(Base, TimestampMixin):
    user_id: Mapped[int] = mapped_column(ForeignKey("user.id"), primary_key=True)
    product_id: Mapped[int] = mapped_column(ForeignKey("product.id"), primary_key=True)
    messages: Mapped[list[dict]] = mapped_column(JSONB, default=list)
```


### 3. 封装 AI 工具

业务 Service 不直接操作 OpenAI SDK，而是使用一个轻量的 `AIChat` 封装。它只负责三件事：

1. 定义统一的消息结构。
2. 调用 OpenAI 兼容接口。
3. 提取流式响应中的文本片段。

业务层只需要传入消息，然后通过 `async for` 获取回答：

```python
async for chunk in ai_chat.chat_stream(messages):
    print(chunk, end="")
```

::: code-group

```python [duyi_utils/ai/chat.py]
from collections.abc import AsyncGenerator, Iterable
from dataclasses import dataclass
from enum import StrEnum
from typing import cast

from openai import AsyncOpenAI
from openai.types.chat import ChatCompletionMessageParam


class MessageRole(StrEnum):
    SYSTEM = "system"
    USER = "user"
    ASSISTANT = "assistant"


@dataclass
class AIMessage:
    role: MessageRole
    content: str


@dataclass
class AIChatConfig:
    api_key: str
    base_url: str = "https://api.openai.com/v1"
    model: str = "gpt-4o"


class AIChat:
    def __init__(self, config: AIChatConfig):
        self._config = config
        self._client = AsyncOpenAI(
            api_key=config.api_key,
            base_url=config.base_url,
        )

    async def chat_stream(
        self, messages: Iterable[AIMessage]
    ) -> AsyncGenerator[str, None]:
        payload = cast(
            list[ChatCompletionMessageParam],
            [{"role": msg.role.value, "content": msg.content} for msg in messages],
        )

        response = await self._client.chat.completions.create(
            model=self._config.model,
            messages=payload,
            stream=True,
        )

        async for chunk in response:
            delta = chunk.choices[0].delta
            if delta.content:
                yield delta.content
```

:::

`stream=True` 表示模型会持续返回片段。`yield` 将每个片段交给上层，因此可以实现前端的打字机效果。

### 4. 设计 service

Service 层负责业务编排，不负责 HTTP 细节，也不负责 OpenAI SDK 细节。可以先从用户动作反推需要的公开方法：

```text
用户可以有以下功能

1. 查看历史对话     get_history()
2. 初始化 AI 导购   initialize()
3. 发送问题         send_message_stream()
4. 删除对话         delete_conversation()
```

再从这些业务动作中提取公共的内部能力：

```text
查询商品            _load_product()
生成系统 Prompt     _render_system_prompt()
读取 AI 配置        _get_required_ai_config()
查询会话            _get_conversation()
```

因此，Service 的方法不是凭感觉设计的，而是由“用户能做什么”和“每个动作需要哪些数据”推导出来的。

#### 4.1 查询商品并生成 Prompt

Prompt 决定 AI 能知道哪些商品信息。先列出 AI 需要的内容，再反推数据库查询：

```text
商品名称、品牌、描述  → Product
商品分类              → Product.categories
SKU、价格、库存       → Product.skus
```

由于当前项目使用异步 SQLAlchemy，分类和 SKU 需要使用 `selectinload` 预加载。然后将 ORM 对象整理成模板需要的字典。

::: code-group

```python [service/template/product_intro.j2]

产品名称：{{ product.name }}
品牌：{{ product.brand or "暂无" }}
描述：{{ product.description or "暂无" }}
分类：{{ product.categories or "暂无" }}
SKU列表：
{% if product.skus -%}
{% for sku in product.skus -%}
  - {{ sku.sku_code }}：价格 ¥{{ sku.price }}，库存 {{ sku.stock }}
{% endfor -%}
{% else -%}
暂无
{% endif -%}

请根据以上信息，向用户介绍这款产品，包括产品特点、品牌、功效、规格选项、适合人群等方面，语气亲切专业。
```

```python [service/ai_service.py]
async def _load_product(self, product_id: int) -> Product:
    result = await self.db.execute(
        select(Product)
        .options(selectinload(Product.categories), selectinload(Product.skus))
        .where(Product.id == product_id)
    )
    return result.unique().scalar_one()


def _render_system_prompt(self, product: Product) -> str:
    template = _jinja_env.get_template("product_intro.j2")
    categories_str = "、".join(c.name for c in product.categories) or None
    skus = [
        {"sku_code": s.sku_code, "price": str(s.price), "stock": s.stock}
        for s in product.skus
    ]
    return template.render(
        product={
            "name": product.name,
            "brand": product.brand,
            "description": product.description,
            "categories": categories_str,
            "skus": skus or None,
        }
    )
```

#### 4.2 读取 AI 配置和查询会话

AI 配置集中读取，避免业务流程到处操作 `Setting` 表。读取后检查三个配置是否完整，再构造 `AIChatConfig`。

会话查询统一使用 `user_id + product_id`，这样可以保证用户只能操作自己针对某个商品的会话。

```python
async def _get_required_ai_config(self) -> AIChatConfig:
    keys = ["ai_api_key", "ai_base_url", "ai_model"]
    result = await self.db.execute(select(Setting).where(Setting.key.in_(keys)))
    settings_map = {s.key: s.value for s in result.scalars().all()}

    missing = [key for key in keys if not settings_map.get(key)]
    if missing:
        raise AiException(
            message="AI服务配置不完整，请联系管理员",
            detail=f"缺少以下配置项：{', '.join(missing)}",
        )

    return AIChatConfig(
        api_key=settings_map["ai_api_key"],
        base_url=settings_map["ai_base_url"],
        model=settings_map["ai_model"],
    )


async def _get_conversation(
    self, user_id: int, product_id: int
) -> AiConversation | None:
    result = await self.db.execute(
        select(AiConversation).where(
            AiConversation.user_id == user_id,
            AiConversation.product_id == product_id,
        )
    )
    return result.scalar_one_or_none()
```

#### 4.3 获取历史流程

用户打开商品页面时，先查询之前是否有会话：

```text
API 接收 product_id
  ↓
获取当前登录用户 user_id
  ↓
查询 user_id + product_id 会话
  ↓
没有会话 → 返回 []
  ↓
有会话 → 过滤 system 消息
  ↓
返回 user 和 assistant 消息
```

数据库中需要保留 system 消息，因为后续请求还要把它发送给 AI；但返回给前端时不返回 system 消息，避免暴露内部提示词。

```python
async def get_history(self, user_id: int, product_id: int) -> list[dict]:
    conv = await self._get_conversation(user_id, product_id)
    if conv is None:
        return []
    return [m for m in conv.messages if m["role"] != "system"]
```

#### 4.4 初始化 AI 导购流程

初始化用于用户第一次进入商品详情页时，让 AI 自动生成商品介绍：

```text
查询已有会话
  ↓
如果已经有有效历史 → 拒绝重复初始化
  ↓
查询商品、分类、SKU
  ↓
生成 system prompt
  ↓
读取 AI 配置
  ↓
调用 AIChat
  ↓
流式生成商品介绍
  ↓
同时拼接完整回答
  ↓
保存 system + assistant 消息
```

为什么既要 `yield`，又要拼接 `full_response`？

```text
yield chunk          → 让上层实时返回内容
full_response += chunk → 流结束后保存完整回答
```

```python
async def initialize(
    self, user_id: int, product_id: int
) -> AsyncGenerator[str, None]:
    conv = await self._get_conversation(user_id, product_id)

    if conv is not None and len(conv.messages) > 1:
        raise AiException(message="该产品已有对话历史记录，请先清空后再初始化")

    product = await self._load_product(product_id)
    system_prompt = self._render_system_prompt(product)
    config = await self._get_required_ai_config()
    ai_chat = AIChat(config)

    full_response = ""
    async for chunk in ai_chat.chat_stream(
        [AIMessage(role=MessageRole.SYSTEM, content=system_prompt)]
    ):
        full_response += chunk
        yield chunk

    messages = [
        {"role": "system", "content": system_prompt},
        {"role": "assistant", "content": full_response},
    ]

    if conv is None:
        self.db.add(
            AiConversation(
                user_id=user_id,
                product_id=product_id,
                messages=messages,
            )
        )
    else:
        conv.messages = messages
        await self.db.merge(conv)

    await self.db.flush()
```

#### 4.5 发送消息流程

模型没有持久化记忆，每次请求都必须携带历史消息：

```text
查询会话
  ↓
不存在 → 提示先初始化
  ↓
读取 JSONB 中的历史消息
  ↓
转换为 AIMessage
  ↓
追加当前 user 消息
  ↓
调用 AIChat
  ↓
流式返回 assistant 内容
  ↓
拼接完整回答
  ↓
追加 user + assistant 消息
```

```python
async def send_message_stream(
    self, user_id: int, product_id: int, content: str
) -> AsyncGenerator[str, None]:
    conv = await self._get_conversation(user_id, product_id)
    if conv is None:
        raise AiException(message="未找到对话记录，请先初始化AI导购")

    ai_messages = [
        AIMessage(role=MessageRole(m["role"]), content=m["content"])
        for m in conv.messages
    ]
    ai_messages.append(AIMessage(role=MessageRole.USER, content=content))

    config = await self._get_required_ai_config()
    ai_chat = AIChat(config)

    full_response = ""
    async for chunk in ai_chat.chat_stream(ai_messages):
        full_response += chunk
        yield chunk

    conv.messages = [
        *conv.messages,
        {"role": "user", "content": content},
        {"role": "assistant", "content": full_response},
    ]
    await self.db.merge(conv)
    await self.db.flush()
```

#### 4.6 删除会话

删除会话用于“重新开始对话”。删除后再次初始化，会重新读取商品资料并生成新的 system prompt：

```python
async def delete_conversation(self, user_id: int, product_id: int) -> None:
    conv = await self._get_conversation(user_id, product_id)
    if conv is not None:
        await self.db.delete(conv)
        await self.db.flush()
```

### 5. 设计异常处理

AI 导购的异常可以从业务流程中推导出来：

```text
AI 配置不完整       → 无法调用模型
重复初始化         → 已经存在有效对话
未初始化发送消息   → 没有上下文，无法继续对话
商品不存在         → 无法生成商品 Prompt
```

AI 相关业务错误使用独立的 `AiException`，并继承项目已有的 `BusinessException`，这样可以继续复用全局异常处理器。

::: code-group

```python [exception/ai.py]
from zy_python_project.exception.base import BusinessException


class AiException(BusinessException):
    def __init__(self, message: str, *, detail: str = ""):
        super().__init__(message=message, detail=detail)
```

:::

商品不存在属于资源不存在问题，应使用项目已有的 `NotFoundException`。OpenAI SDK 的网络错误、超时等底层异常，后续可以在 AI 工具层或 Service 层统一转换。

## 总结

从 0 实现这个功能时，可以按照下面的顺序推进：

```text
1. 明确业务范围：先做商品资料 + 多轮对话
2. 设计 AiConversation：保存用户、商品和消息历史
3. 增加 AI 配置：API Key、Base URL、Model
4. 封装 AIChat：隐藏 OpenAI SDK 和流式响应细节
5. 编写商品 Prompt 模板
6. 从用户动作推导 AiService 方法
7. 实现历史、初始化、发送消息和删除流程
8. 增加统一异常处理
9. 最后由 API 层接入认证和 StreamingResponse
```

最终的核心链路是：

```text
Product
  ↓
商品 Prompt
  ↓
AIChat 流式调用
  ↓
AiConversation.messages
  ↓
下一轮对话继续携带历史
```
