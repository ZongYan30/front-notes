Webhook **只负责触发**。Langfuse 不会替我们运行这个 Python Agent，也不会因为回调返回 `202` 就自动产生实验结果。

## 打通 Langfuse 到 Agent Server 的访问链路

Langfuse 对 Webhook 有以下要求：

- Webhook的地址端口号必须是`80`或`443`
- Webhook的域名必须在白名单中

现在需要解决白名单的问题。

在本地开发场景中，Langfuse 在容器内部，而我们的 Agent Server 在宿主机。容器内部要访问宿主机，除了 IP 之外，还可以使用一个特殊域名：`host.docker.internal`。

因此现在必须把该域名加入到白名单。

1. 在 **Langfuse 工程**（不是本工程）的 `.env` 中加入：

   ```
   LANGFUSE_WEBHOOK_WHITELISTED_HOST=host.docker.internal
   ```

2. 覆盖`docker-compose.yml`文件
   文件去工程中找，实际上就是配置了这一句白名单
   ```yaml
   LANGFUSE_WEBHOOK_WHITELISTED_HOST: ${LANGFUSE_WEBHOOK_WHITELISTED_HOST:-}
   ```
3. 重启服务器

   ```
   docker compose up -d --no-deps --force-recreate langfuse-web langfuse-worker
   ```

4. 验证环境变量是否注入
   ```
   docker compose exec langfuse-web printenv LANGFUSE_WEBHOOK_WHITELISTED_HOST
   docker compose exec langfuse-worker printenv LANGFUSE_WEBHOOK_WHITELISTED_HOST
   ```

## 配置 langfuse 实验回调

1. 点击`Run experiment`，选择`via Webhook`，选择一个数据集，点击`Configure`
2. 配置回调
   1. URL地址填写：`http://host.docker.internal/api/webhooks/langfuse/experiments`
   2. 启用`Sign requests`
   3. 将生成的`secret`保存到`Agent Server`工程的环境变量中

此时,langfuse侧的准备已完成，发送请求需要agentServer的支持，所以接下来需要agentServer来支持

## 为 Agent Server 添加自定义地址

1. 配置`langgraph.json`，加入：

   ```json
     "http": {
       "app": "ai_eval.app.main:app", //ASGI应用
       "enable_custom_route_auth": false //禁止走之前定义的auth验证
     }
   ```

这里相当于配置了一个ASGI应用，用于接收langfuse的webhook请求。
app内的接口主要为了：1. 调用执行实验 2. 返回实验结果

2. 安装`fastapi`

   ```shell
   uv add fastapi
   # 此工程使用
   uv sync
   ```

3. 完成模块`ai_eval.app.main`
   app应用主要职责：

- 环境变量新增：`LANGFUSE_WEBHOOK_SECRET`,config中的langfuse_settings新增：`experiment_webhook_secret`配置 (验证工具需要使用)
- 验证langfuse实验的webhook的身份签名 (验证工具可以由AI生成)
- 从请求拿到数据集名称，调用`run_benchmark`函数执行实验

```python [src/ai_eval/app/experiment_webhook.py]
from fastapi import APIRouter, Request, BackgroundTasks
from fastapi.responses import JSONResponse
from ai_eval.utils.langfuse_signature import verify_signature
from ai_eval.config.langfuse_settings import langfuse_settings
from ai_eval.benchmarks.benchmark import run_benchmark

router = APIRouter()


@router.post("/api/webhooks/langfuse/experiments")
async def start_experiment(request: Request, background_tasks: BackgroundTasks):
    # 1. 验证签名 传入request 再从环境变量中读出webhook_secret
    isvalid = await verify_signature(
        request, langfuse_settings.experiment_webhook_secret
    )
    if not isvalid:
        return JSONResponse({"error": "Invalid Webhook Signature"}, status_code=401)
    # 2. 启动实验
    body = await request.json()
    dataset_name = body["datasetName"]

    # 3. fastapi提供了后台运行的功能，如果长时间阻塞到这里，webhook那边会报错。
    # 这里使用fastapi的后台运行新开一个线程执行任务即可。（声明参数类型会自动DI注入）
    background_tasks.add_task(run_benchmark, dataset_name)
    return JSONResponse({"ok": True}, status_code=202)
```

```python [src/ai_eval/utils/langfuse_signature.py]
import hashlib
import hmac

from fastapi import Request


async def verify_signature(request: Request, secret: str) -> bool:
    """验证 Langfuse 请求签名；无密钥或签名无效时返回 False。"""
    if not secret:
        return False

    signature_header = request.headers.get("x-langfuse-signature", "")
    parts = signature_header.split(",")
    if (
        len(parts) != 2
        or not parts[0].startswith("t=")
        or not parts[1].startswith("v1=")
    ):
        return False

    timestamp = parts[0][2:]
    signature = parts[1][3:]
    if not timestamp or not signature:
        return False

    try:
        received = bytes.fromhex(signature)
    except ValueError:
        return False

    expected = hmac.new(
        secret.encode("utf-8"),
        timestamp.encode("utf-8") + b"." + await request.body(),
        hashlib.sha256,
    ).digest()
    return hmac.compare_digest(received, expected)
```

## webhook签名验证原理

了解一下webhook签名验证原理

```
langfuse post请求 --> 生成签名
  签名：hmac_sha256(密钥.时间戳.请求体)
  x-langfuse-signature: t=时间戳,v1=签名

AgentServer --> 用相同方式再算一次
  签名：hmac_sha256(密钥.时间戳.请求体)

一样就验证通过
```

> 类似jwt的验证原理
