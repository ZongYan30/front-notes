# 会话session
session是服务器和客户端之间进行交互的一个临时会话，session是服务器存储在客户端上的数据。
session一般是和cookie一起使用的，cookie一般用来保存sessionId，sessionId一般保存在服务器上。

cookie:
优点: 存储在客户端，不占用服务器资源
缺点: 只能是字符串格式 存储量有限 数据容易被获取篡改 容易丢失

session:
优点: 存储在服务器端，可以是任何格式，存储量理论上是无限的，数据难以被获取篡改，不容易丢失
缺点: 占用服务器资源

> 一般sessionId会使用uuid生成。

![session示意图](https://zongyan30.github.io/front-assets/Node/session.jpg)


一个sessionId会读取到对应的session数据,而不是整个session表。

## 使用session登录
### 1. 安装express-session
```sh
npm install express-session -S
```
---
> express-session是一个中间件，会给req添加一个session属性，用于存储session数据。

### 2. 使用session中间件
`init.js`

```js 
const session = require("express-session");

//一般session使用会放在最上面
app.use(
  session({
    secret: "yuan",//加密密钥
    name: "sessionid",//cookie的名称
  })
);

//其它中间件...
```
---
> 当用户第一次登录的时候，会创建一个sessionId，并保存在客户端的cookie中。下次请求的时候，会从cookie中获取sessionId，然后从服务器端获取对应的session数据。

`login.js`登录路由记录登录信息

```js
router.post( "/login",asyncHandler(async (req, res) => {
    const result = await adminServ.login(req.body.loginId, req.body.loginPwd);
    if (result) {
      // 生成token
      let token = cryptor.encrypt(result.id.toString());
      //将user信息存储在当前的session中
      req.session.loginUser = result;
    }
    return result;
  })
);
```

回到校验token中间件 `tokenMiddleware.js`

```js
module.exports = function (req, res, next) {
    // 校验白名单
    const apis = needTokenApi.filter(item => {
        const reg = pathToRegexp(item.path);
        return item.method == req.method && reg.regexp.test(req.path);
    })

    if (!apis.length) {
        next();
        return;
    }

    // 校验是否已登录
    if (!req.session.loginUser) {
        hasNoToken(res);
        return;
    }

    next();
}
```

## 注意
* session一般是存储在内存中的，服务器重启后，session数据会丢失。
* 当应用规模较大时，需要将session数据存储在数据库中，而不是内存中,推荐redis。
